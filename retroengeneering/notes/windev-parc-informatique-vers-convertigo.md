Le 2026-09-11, l'exemple officiel PC SOFT `PCSOFT-WINDEV-code-source/WD-Gestion-de-Parc-informatique` (WinDev 28, format texte) a été cloné et analysé pour reconstruire ses écrans avec le MCP Convertigo. Livrables envoyés à l'utilisateur (fichiers) : `ANALYSE_ECRANS.md` (fiches des 11 fenêtres, modèle de données, règles, correspondance NGX), `convertigo-crud-spec.json` (spec `upsert-crud` : entités lieux/utilisateurs/fournisseurs/modeles/machines/composants, 5 relations, hints UI, seed de démo issu des vrais fichiers HFSQL) et un zip avec wireframes SVG + scripts. Synthèse publiée en artefact : https://claude.ai/code/artifact/6c1f5f87-2ff5-44bc-9b4a-d115c1842037 (page « Écrans WD Gestion de Parc », à mettre à jour via `url`). Un second exemple, `WD-Gestion-Contacts`, avait aussi été cloné comme alternative plus simple.

Le 2026-09-11 (suite), le rail CRUD a été exécuté : projet Convertigo `ParcInformatique` importé depuis template_ngxBuilderIonic, `upsert-crud` avec HSQLDB embarqué (connecteur `ParcInformatiquedb`, façades `parc_*`, entités emplacements/utilisateurs/fournisseurs/modeles/machines/composants, seed de démo 4 machines complètes), kit UI entity-pages bootstrap + final, viewer vert sur http://localhost:47242/home, projet sauvegardé. Pièges rencontrés : `database.mode` est obligatoire (valeur `hsqldb`), et une entité nommée `lieux` (pluriel irrégulier) fait échouer la validation `seed.data` même avec `singular`/`plural` ; contournement = entité `emplacements`. La preuve reste « partial » sur les 5 vérifications d'alias de libellé des séquences `*_by_*` faute d'échantillon de ligne parente côté outil de preuve, alors que les transactions SQL renvoient bien les alias.

**Why:** l'utilisateur veut démontrer/industrialiser la reconstruction d'applications WinDev en Convertigo.

Puis les écrans spécifiques ont été construits par `databaseobject-tree-apply` (un sous-arbre peu profond par appel, les arbres imbriqués sur plus de ~9 niveaux et `batch-call` font échouer le parsing des arguments côté harness) : page `ParcPage` (segment `/parc`, équivalent FEN_Principale : liste des machines, plan des locaux en divs positionnées d'après `emplacements.rectangle`, compteur par salle, filtre au clic, boutons Nouvelle/Modifier vers `/machine` via le global `parcMachineId`) et page `MachineDetailPage` (segment `/machine` : onglets Machine/Composants, réutilise les composants partagés du kit `MachinesEditForm` et `ComposantsEditForm` avec `DraftSeed` pré-rempli, liste `parc_list_composants_by_machine`, panneau modèle à libellés dynamiques via `parc_read_modele`, boutons Dissocier/Ajouter depuis le stock sur les nouvelles façades `parc_unlink_composant`/`parc_link_composant`). Compilation verte, projet sauvegardé, comportement runtime non vérifié en navigateur (Playwright MCP absent de la session).

Seconde passe le 2026-09-11 ("toute la liste") : pages `LieuxPage` (/lieux, plan cliquable, tracé d'un lieu en deux clics, contrôle de chevauchement, confirmation « Le lieu vous convient-il ? »), `ModelesGestionPage` (/modeles-gestion, table + fiche à libellés dynamiques), `UtilisateursGestionPage` (/utilisateurs-gestion, civilité en liste + photo ou icône homme/femme), `RapportsPage` (/rapports, six états HTML avec impression navigateur, paramètre machine/modèle, reçus par les globaux `parcReport`/`parcReportId`), suppression de machine à trois options dans ParcPage (façades `parc_delete_machine_with_composants` / `_keep_composants`), règles de suppression : DELETE gardés par NOT EXISTS + champ `refs` renvoyé par chaque `parc_delete_*` + toast WinDev dans les formulaires du kit, sélecteurs enrichis dans MachinesEditForm/ComposantsEditForm (aperçu de l'élément choisi + bouton Nouveau qui ouvre le formulaire partagé de l'entité liée puis sélectionne l'élément créé). Compilation verte, projet sauvegardé, comportement runtime non vérifié en navigateur.

Troisième passe le 2026-09-11 ("revoit l'ergonomie et le responsive... charte graphique moderne, tons bleus") : pages du kit en liste | fiche | formulaire côte à côte (colonnes 3/4/5 xl, 4/4/4 lg, 5/7 md) avec liste défilante et ligne sélectionnée (variable `SelectedId` ajoutée aux `*ListPanel`), MachineDetailPage en trois colonnes sans onglets, plan des locaux en pourcentages (ratio 709×538, clics recalés), barres `parc-toolbar`, cartes d'accès aux écrans WinDev sur Home, bouton menu dans `sp:CrudPageHeader` (bean `UIDynamicElement#MenuButton`), libellés du kit en français, style applicatif `sl:ParcTheme` (palette bleue #1d4ed8 / #0b2a6f / #0284c7, fond #eef3fb, dégradé de bandeau, mode sombre). Vérifié dans le viewer (http://localhost:47242) : Home, Lieux (kit), Parc, Gestion des lieux, Modèles, Utilisateurs, États, Fiche machine ; compilation verte. Incident : une fusion tree-apply a vidé les colonnes des six pages du kit ; panneaux reconstruits à l'identique (voir [[convertigo-ngx-tree-apply-pieges]]).

**How to apply:** tout le périmètre WinDev est couvert ; les prochaines demandes probables sont des tests runtime ou des retouches visuelles. Écrans spécifiques (page Home machines + plan cliquable, fiche machine à onglets avec composants). Voir [[windev-format-texte-et-hfsql]] et [[pcsoft-depots-exemples-windev]].
